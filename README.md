# Polymarket Whale Tracker

Бот отслеживает «умные деньги» на Polymarket: находит кошельки с высоким WinRate/PnL и «инсайдерские» молодые кошельки с крупными ставками, ловит их сделки в реальном времени, оценивает консенсус и шлёт сигнал в Telegram. Опционально повторяет сделку (по умолчанию — **paper-режим**).

Стратегия описана в [docs/Requirements Polymarket.md](docs/Requirements%20Polymarket.md). Ниже — как это реализовано в коде, шаг за шагом.

## Алгоритм торговли

Полный путь: **кошелёк кита совершает сделку → бот её замечает → превращает в сигнал → проходит гейты входа → открывает позицию → управляет выходом → результат уходит в петлю обратной связи.** Каждый шаг ниже соответствует конкретной функции в коде.

```
Кит торгует на Polymarket
        │
        ▼
① Whale Scouter (src/scout.py) — офлайн, по расписанию
   отбирает КАКИХ китов вообще отслеживать → таблица `whales`
        │
        ▼
② Live Tracker: опрос (src/tracker.py, run())
   round-robin по /trades?user=<кит> раз в 30 сек
        │
        ▼
③ Filter Engine (src/engine.py, evaluate_market())
   сырые сделки → СИГНАЛ (сторона, консенсус, цена) или ничего
        │
        ▼
④ Гейты входа (src/tracker.py, execute_trade())
   сигнал → допустить к деньгам или пропустить (⏭)
        │
        ▼
⑤ Sizing (position_size_usd()) → ⑥ Ордер (src/trader.py) → позиция открыта
        │
        ▼
⑦ Управление позицией (manage_positions(), каждые 30 сек)
   частичная фиксация / TP / SL / закрытие по времени / по разрешению рынка
        │
        ▼
⑧ Петля обратной связи (signal_outcomes, каждые 30 мин)
   был ли кит прав? → авточистка плохих китов
```

### ① Отбор китов — Whale Scouter

Запускается отдельно (по cron/systemd-таймеру), не в торговом цикле. Источники кандидатов:
- **Leaderboard** (`/v1/leaderboard?rankType=pnl`) — топ-50 по PnL, самый стабильный сигнал качества.
- **Лента активных сделок** (`/trades`, последние ~5000) — нужна, чтобы ловить молодых «инсайдеров», которых на leaderboard ещё нет.

Каждый кандидат скорится по `/positions` (`score_wallet()` в [src/scout.py](src/scout.py)): `total_pnl = Σ(realizedPnl + cashPnl)`, позиция считается решённой при `redeemable=true` либо цене у экстремума (`≤0.03` / `≥0.97`), `winrate = wins / resolved`. Кошелёк проходит в БД (`qualifies()`), если выполняется любое из трёх условий (текущие дефолты `ScoutConfig`, могут быть переопределены в `.env`):

| Тип | Условие |
|---|---|
| 💎 Бриллиант | WinRate ≥ 55% **и** Total PnL ≥ $1k **и** ≥ 2 разрешённых позиций |
| 🥷 Инсайдер | Возраст кошелька < 7 дней **и** объём сделок > $50k **и** WinRate ≥ 50% **и** PnL > $0 |
| 🏆 Leaderboard-кит | lifetime PnL с leaderboard ≥ $25k (WinRate ≥ 50% проверяется только если решённых позиций достаточно для статистики) |

> `/positions` — снапшот текущего портфеля кошелька, а не lifetime-история, поэтому пороги сознательно мягче, чем в бизнес-требованиях (`docs/Requirements Polymarket.md` целится в WinRate ≥ 80% / PnL ≥ $100k как в *желаемый профиль* кита) — иначе снапшот почти никого не пропускает. Расхождение см. в [src/scout.py](src/scout.py) (docstring `_score_positions`/`qualifies`).

Внутри этого множества выделяется подмножество **элитных** китов (`db.get_elite_addresses`: WinRate ≥ 70% и PnL ≥ $10k, либо инсайдер, либо leaderboard-кит) — только им разрешено давать сигнал в одиночку (см. шаг ③). Пороги — в `ScoutConfig` / `.env` (`SCOUT_MIN_WINRATE`, `SCOUT_MIN_PNL`).

### ② Мониторинг — опрос китов

Главный цикл (`run()` в [src/tracker.py](src/tracker.py)) не читает общую ленту сделок Polymarket: лимитные ордера китов там не видны (сделка в общей ленте атрибутируется тейкеру). Вместо этого — **персональный round-robin опрос** `/trades?user=<адрес>` по 25 китов за тик (`whales_per_cycle`), каждые 30 сек (`poll_interval`). Найденные сделки:
1. Дедуплицируются по `tx_hash + outcome`.
2. Отфильтровываются по принадлежности отслеживаемым китам и по `notional ≥ $50` (`min_size_usdc`).
3. Регистрируются в анти-MEV детекторе (`engine.observe()`): кошелёк с ≥50 сделками за 60 сек мьютится на час — это бот-арбитражёр, не «умные деньги».
4. Копятся в скользящем буфере 12 часов (`signal_window`), сгруппированные по рынку (`cond_id`).

Рынки, подпадающие под regex-фильтр шума (`MarketFilterConfig.should_skip`) — спорт (NBA/NFL/UFC/soccer…), почасовые up/down, крипто price-prediction — не доходят до Filter Engine вообще.

### ③ Filter Engine — сделки → сигнал

`FilterEngine.evaluate_market()` в [src/engine.py](src/engine.py) превращает пул сделок по одному рынку в сигнал одним из двух способов:

- **Trusted whale (одиночный сигнал).** Если хотя бы один **элитный** кит (см. шаг ①) сделал ставку с notional ≥ $1,000 (`trusted_whale_min_notional`) — сигнал сразу, консенсус не нужен.
- **Consensus (групповой сигнал).** Иначе нужно ≥ 2 кошелька (`min_wallets`) на одной стороне, с перевесом над противоположной ≥ 2× (`consensus_dominance`), и суммарный notional группы ≥ $200 (`min_alert_notional`).

Сигнал несёт: сторону (BUY/SELL), `median_price` (медиана цен входа китов группы — ориентир, «по чём заходил кит»), исход-консенсус (самый частый outcome), и флаг `delta_neutral` — эвристика, что часть китов одновременно в противоположных исходах (возможен хедж, а не направленная ставка).

### ④ Гейты входа — execute_trade()

Прежде чем сигнал станет ордером, он проходит цепочку проверок в `execute_trade()` ([src/tracker.py](src/tracker.py)). Проверки идут по порядку, первая же непройденная — причина пропуска (алерт `⏭ Пропуск (...)` в лог; в Telegram уходят только реально исполненные/проблемные статусы):

| # | Проверка | Порог |
|---|---|---|
| 1 | Цена кита в адекватном диапазоне | `0.01 ≤ median_price < 1` |
| 2 | Лимиты экспозиции (`entry_blocked`) | ≤ 10 открытых позиций, не более одной на рынок |
| 3 | Рынок ещё торгуется | `get_market_tokens` ≠ `CLOSED` |
| 4 | Есть токен нужного исхода | `resolve_token_id` нашёл tokenId |
| 5 | Есть цена в стакане и она разумна | `0.01 ≤ ask < 1` и `ask ≤ 0.80` (`max_price`) |
| 6a | *Только одиночный кит:* не SELL | `single_whale_allow_sell=False` — SELL одиночного кита режется |
| 6b | *Только одиночный кит:* не фаворит | `ask < 0.50` (`single_whale_max_price`) — фавориты только консенсусом |
| 6c | *Только одиночный кит:* не лотерея | `ask ≥ 0.20` (`cheap_consensus_below`) — вход дешевле только консенсусом |
| 6d | *Только одиночный кит:* есть край | `WinRate кита > ask` (`skip_when_no_edge`), иначе ставка вслепую |
| 7 | Рынок не «убежал» от кита | `ask − ref_price ≤ 0.05` (`max_entry_slippage`; `ref_price = median_price` при BUY, `1 − median_price` при SELL) |
| 8 | *Только дешёвый вход (<0.35):* горизонт разрешения | `endDate рынка − сейчас ≤ 7 дней` (`cheap_max_horizon_days`), иначе вход пропускается |
| 9 | Баланс достаточен и не в дневном стопе | `balance ≥ $1` и просадка дня `< 5%` (`daily_max_loss_pct`) |

Шаги 6a–6d действуют **только** для одиночного сигнала (`signal_type == "trusted_whale"`) — у консенсуса край в самой группе китов, а не в WinRate одного из них, поэтому эти гейты консенсус не проходит.

### ⑤ Sizing — сколько поставить

`position_size_usd()` считает размер позиции по **fractional Kelly**:

```
p = min(WinRate лучшего кита сигнала, 0.95)     # прокси вероятности
c = цена входа (ask)
f* = (p − c) / (1 − c)                           # доля Келли, если есть край (p > c)
размер = clamp(balance × 0.25 × f*, $2, balance × 2%)
```

Если `p ≤ c` (WinRate кита не выше цены — по нашей оценке край не подтверждён), ставится минимум `$2` (`trade_amount_usd`). Кап на позицию — 2% банкролла (`position_max_pct`) для любой цены входа; доля Келли — 0.25 от полного (`kelly_fraction`), чтобы не переливеражиться на шумной оценке `p`.

> Раньше дешёвые входы (<0.35) получали повышенный кап 4% («асимметричный край»). Патч G (2026-07-04) вернул его к 2%: за 19.06–03.07 этот бакет дал −$236 при 10/32 прибыльных и ни одного выигранного разрешения — повышенный кап был не подтверждён данными. Вернётся выше, когда `db.signal_outcome_breakdown()` покажет реальную правоту китов на этом бакете.

### ⑥ Исполнение — paper vs live

`src/trader.py` абстрагирует ордер за одним интерфейсом (`place_bet`, `close_position`, `get_usdc_balance`) и переключается флагом `PAPER_MODE`:

| Режим | Поведение |
|---|---|
| `PAPER_MODE=true` (default) | Ордер симулируется по текущей цене, реальных денег нет. Виртуальный банкролл и лента филлов — в `data/paper_fills.json` (через `src/state.py`, атомарная запись) |
| `PAPER_MODE=false` | Реальный ордер через Polymarket CLOB V2 (`py_clob_client_v2`). Нужны ключи `POLY_*` в `.env` |

Открытая позиция сохраняется в `data/open_positions.json`: цена/размер входа, купленный исход, `cond_id`, `close_at` (когда её принудительно закрыть, если раньше не сработает TP/SL/разрешение).

### ⑦ Управление открытой позицией — manage_positions()

Вызывается в начале каждого тика главного цикла (каждые 30 сек), для каждой открытой позиции — **сначала выход, потом новые входы**. TP/SL заданы не в процентах от цены (на бинарном рынке при входе 0.9 «+25%» недостижимы), а в пунктах вероятности, и **зависят от цены входа** (`exit_params()`):

| Бакет входа | Частичная фиксация («флип») | Take Profit | Stop Loss |
|---|---|---|---|
| Дешёвый (`< 0.35`) | выключена — хвост едет целиком | широкий, `+0.45` | **выключен** — едет до TP/разрешения/горизонта |
| Середина (`0.35–0.50`) | `+0.05` → фиксируем 50% | `+0.10` | `−0.15` |
| Дорогой фаворит (`≥ 0.50`) | `+0.03` → фиксируем 50% | `+0.06` | `−0.15` |

Логика (по приоритету, первое сработавшее правило закрывает/режет позицию):

1. **Цена недоступна (404 у CLOB)** → рынок, вероятно, разрешился. Спрашиваем исход у Gamma (`get_market_resolution`) и закрываем по факту (`1.0` выигрыш / `0.0` проигрыш) — не по цене входа, иначе выигрыши считаются нулевыми. Если Gamma тоже не знает — ждём `resolution_grace_hours` (24ч) после `close_at`, потом закрываем нейтрально по цене входа.
2. **Цена ≥ 0.97** → рынок фактически выигран, закрываем немедленно.
3. **Цена ≤ 0.03** → для входов со включённым стопом закрываем как проигрыш немедленно. Для дешёвых входов (стоп выключен) **не закрываем вслепую** — 3 цента на живом рынке (особенно спорт в моменте) часто шум игры, а не разрешение: сначала подтверждаем через `get_market_resolution`, и только при подтверждении фиксируем 0.0. Не подтверждено — едем дальше.
4. **Частичная фиксация («флип»):** если движение цены попало в диапазон `[partial_take_delta, take_profit_delta)` и ещё не фиксировали — продаём долю позиции, остаток продолжает ехать.
5. **Take Profit:** движение ≥ `take_profit_delta` → закрываем всё.
6. **Stop Loss:** если стоп включён и движение ≤ `stop_loss_delta` → закрываем всё.
7. **Время вышло:** `now > close_at` → закрываем по текущей цене. Для дешёвых входов `close_at` = дата разрешения рынка + 2ч буфера (не 24ч-таймер) — иначе стоп-выключенная позиция обрубается таймером раньше, чем успевает дойти до TP или разрешения.

Лимит открытых позиций и дневной стоп-лосс (гейты 2 и 9 в таблице шага ④) не привязаны к конкретной позиции, а действуют на уровне всего бота: новые входы блокируются, но управление уже открытыми позициями (этот шаг) продолжает работать как обычно. Состояние дневного стопа — `data/metrics.json`.

### ⑧ Петля обратной связи — китов проверяют их же сигналы

Каждый сигнал (даже если по нему не открыли позицию — гейты шага ④ его отсеяли) пишется в таблицу `signal_outcomes`: сторона, цена, тип сигнала, участвовавшие кошельки. Каждые 30 минут (`outcome_check_interval`) `check_signal_outcomes()`:
1. Берёт батч из 100 неразрешённых сигналов, **ротируя очередь** — сначала давно не проверенные, среди непроверенных свежие вперёд (не «100 старейших навсегда»).
2. Спрашивает Gamma, разрешился ли рынок; если да — фиксирует, был ли кит прав (`winner == bet` для BUY, наоборот для SELL).
3. Сигналы без `cond_id` или неразрешённые дольше 30 дней (`outcome_give_up_days`) помечаются `gave_up` — выходят из очереди, не блокируя её вечно.
4. `prune_bad_performers`: кит с ≥5 разрешёнными сигналами и долей правоты < 40% удаляется из отслеживаемых.

Диагностика по бакетам цены/типу сигнала — `db.signal_outcome_breakdown()`, видна в `scripts/calibration_check.py` и в ежедневном heartbeat.

```bash
# Зависимости
pip install -r requirements.txt

# Конфиг
cp .env.example .env   # заполнить TELEGRAM_TOKEN, TELEGRAM_CHAT_ID
```

## Запуск

**Шаг 1 — собрать список китов** (Whale Scouter, запускать по cron раз в день):

```bash
PYTHONPATH=. python3 -m src.scout
```

**Шаг 2 — запустить мониторинг** (Live Tracker):

```bash
./run.sh                       # фон, логи → logs/monitor.log
# или напрямую:
PYTHONPATH=. python3 -m src.tracker
```

**Ежедневное обновление китов** — на сервере это делает systemd-таймер
(`deploy/polymarket-scout.timer`); локально: `PYTHONPATH=. python3 -m src.scout`.
