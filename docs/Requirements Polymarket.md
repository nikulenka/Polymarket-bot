Механика сводится к отслеживанию кошельков с высоким WinRate. Это решает две задачи: извлечение профита из сделок смарт-мани и набивка личных объемов под потенциальный дроп токена POLY (запуск намечен на 2026 год \[[01:54](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=114)\]).

## **Ручной ончейн-поиск**

Polymarket работает на смарт-контрактах, поэтому вся статистика кошельков прозрачна и публична \[[01:08](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=68)\].

**1.Выбор ликвидного пула:**Фокус на макро-событиях.  
Откройте крупный инфоповод с высокой ликвидностью — например, ставку ФРС или исход политических выборов \[[03:18](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=198)\].

**2.Анализ вкладки Top Holders:**  
В карточке события перейдите в раздел **Top Holders**, чтобы увидеть адреса крупнейших держателей контрактов «Yes» и «No» \[[06:56](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=416)\].

**3.Профилирование трейдера:**Аудит исторической эффективности.  
Провалитесь в профиль выбранного аккаунта. В разделе **Closed** оцените WinRate, исторический PnL и профильные темы. В разделе **Active** проверьте текущие точки входа и распределение капитала \[[07:58](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=478)\].

## **Исполнение и уязвимости стратегии**

* **Динамическая фиксация (Флиппинг).** Дожидаться разрешения события (Resolution) не обязательно. Если после вашей ставки вероятность сместилась в нужную сторону, контракт можно сразу продать по рынку, зафиксировав курсовую разницу \[[09:24](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=564)\].  
* **Риск дельта-нейтральных позиций.** Слепое копирование опасно. Кит может купить «Yes» на Polymarket и захеджироваться через покупку «No» на альтернативной платформе (например, Kalshi). Для него эта позиция алгоритмически безубыточна и нужна лишь для фарма объемов, тогда как ваша односторонняя ставка может сгореть \[[10:05](https://www.youtube.com/watch?v=NwnU7wWeLJg&t=605)\].

Для автоматизации слежки за китами и инсайдерами Polymarket (особенно молодыми кошельками с крупными ставками) ручной мониторинг не подходит. Ниже представлена архитектура автономного парсера, спроектированная специально под реализацию через **Claude Code**.  
Claude Code идеально подходит для сборки этого инструмента, так как проект требует интеграции с GraphQL, работы со смарт-контрактами и кастомной фильтрации данных без тяжелого фронтенда.

## **🛠 Технологический стек и источники данных**

Поскольку Polymarket работает в сети **Polygon**, мы собираем данные напрямую из блокчейна и официального индексатора (The Graph), минуя ограничения по API веб\-сайта.

* **Язык:** TypeScript / Node.js (минимальный оверхед, нативная поддержка типизации).  
* **Источники данных:**  
  * Polymarket Subgraph (GraphQL) — для получения истории рынков и позиций.  
  * Polygon RPC (Alchemy/QuickNode) — для трекинга транзакций в реальном времени.  
* **База данных:** SQLite (локально, без лишних серверов) для хранения профилей китов, их WinRate и отслеживаемых контрактов.  
* **Уведомления:** Telegram Bot API.

### **1\. Модуль Скоринга («Whale Scouter»)**

Этот компонент работает по расписанию (Cron). Его задача — сканировать топ-холдеров крупных рынков и пополнять базу данных «бриллиантовыми» кошельками.

* **Логика работы:** Делает запрос к Polymarket Subgraph, вытягивает топ-100 адресов из пулов с ликвидностью более $500k.  
* **Фильтрация по критериям из видео:**  
  * Вычисление общего PnL (сумма закрытых позиций).  
  * Расчет WinRate (отношение прибыльных исходов к убыточным).  
  * *Инсайдерский фильтр:* проверка даты первой транзакции кошелька. Если кошелек создан менее 14 дней назад, но баланс сделок превышает $10,000 — ему присваивается наивысший приоритет (метка \[INSIDER-ALERT\]).

### **2\. Модуль Живого Трекинга («Live Tracker»)**

Этот компонент работает постоянно (WebSocket / Long-polling). Он следит за действиями кошельков из базы данных.

* **Логика работы:** Подписывается на события TransferSingle и TransferBatch смарт-контракта **CTF (Conditional Tokens Framework)** Polymarket в сети Polygon.  
* **Что ищет:** Транзакции, где отправителем или получателем является адрес из нашей БД отслеживаемых китов. Как только кит покупает или продает доли исхода (Shares), модуль перехватывает хэш транзакции.

### **3\. Движок Фильтрации и Анализа («Data Engine»)**

Прежде чем отправить уведомление, бот должен отсеять шум.

* **Проверка на спреды и арбитраж:** Если кошелек совершает по 50 транзакций в минуту на микро-суммы, движок классифицирует его как торгового бота (MEV/Arbitrage) и временно мьютит, чтобы избежать спама.  
* **Калькулятор объема:** Оповещение срабатывает только в том случае, если эквивалент ставки кита превышает заданный порог (например, \> $1,000).

### **4\. Модуль Уведомлений («Alert Telegram»)**

Формирует понятный человеку сигнал. Внутри сообщения обязательно должны быть:

1. Ссылка на рынок Polymarket.  
2. Суть ставки (Кит зашел в "YES" или "NO").  
3. Статистика кошелька (WinRate, PnL, возраст).  
4. Цена контракта в момент входа (чтобы вы могли оценить потенциал флиппинга).
