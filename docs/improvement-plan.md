## Диагноз

Выигрышных сделок не мало (76.5%). Проблемы — мелкий выигрыш и нереализованный потенциал:

1. **🔴 Петля обратной связи была мертва (баг).** `api.get_market_resolution` фильтровал
   Gamma по `conditionId` — параметр игнорируется, возвращался случайный список рынков,
   `data[0]` — посторонний рынок → всегда `None`. Итог: 0 из 188 сигналов разрешено,
   `prune_bad_performers` ни разу не сработал, а тот же вызов в `manage_positions`
   ронял разрешённые позиции в ветку «исход неизвестен» → закрытие по входу (конфискация
   выигрышей). **Исправлено** (см. P0 ниже): параметр → `condition_ids` + рынок считается
   разрешённым по `closed` ИЛИ (`endDate` прошёл И цена ≥ 0.99), т.к. Polymarket держит
   `closed=False` ещё долго после фактического исхода (UMA-задержка, `disputed`).

2. **🔴 Качество китов просело.** Средний winrate отслеживаемых китов 43%, средний PnL
   −$105k. Только 14 из 65 проходят winrate ≥ 0.8. Есть киты с winrate 0.00 и PnL −$8.8M
   (LEEEROYJENKINS), −$5.7M — попали через leaderboard и не вычищались (петля мертва).
   Пороги занижены: `min_winrate=0.55`, `min_total_pnl=$1k` против стратегии (0.80 / $100k).
   82% сигналов — одиночный «элитный» кит, а не консенсус 2+.

3. **🟠 Асимметрия выходов (R/R 0.70).** TP +10c, но SL −15c + флип фиксирует 50% уже на
   +5c. Выигрыш ограничен ~+18%, убыток доезжает до −26% (SL) или −100% (разрешение против
   нас: 7 сделок = −36.63). Для 76% попаданий это математически вывернуто.

4. **🟠 Малый абсолютный выигрыш** — не из-за недосайзинга (позиции в капе 2% = $19.6),
   а из-за банкролла $1000 и раннего обрезания прибыли флипом/тесным TP.

5. **🟡 ~half рынков не разрешается** даже после фикса: 46 из 99 (быстрые спорт-халфтаймы)
   отсутствуют в Gamma по `condition_ids`. Их сигналы остаются pending. Отдельная задача.

## План

Порядок строгий: **P0 → 3–5 дней сбора исходов → мерить → P1/P2 на данных.**

### P0 — починить петлю обратной связи ✅ СДЕЛАНО
- `src/api.py` `get_market_resolution`: `conditionId` → `condition_ids`; разрешение по
  `closed` ИЛИ (`endDate` прошёл И цена ≥ 0.99). Тесты: `TestMarketResolution`.
- *Эффект:* запускает авточистку китов и корректное закрытие разрешённых позиций по
  1.0/0.0 (возврат конфискованных выигрышей). Без этого остальное работает вслепую.

### P1 — качество сигнала (↑ число выигрышей)
- Поднять пороги ближе к стратегии: `min_winrate 0.55→0.65`, `min_total_pnl $1k→$25k`,
  `lb_min_winrate 0.50→0.60` (`src/config.py`).
- После 3–5 дней набора исходов ужесточить `prune_min_winshare 0.40→0.50`.
- Консенсус 2+ — основной сигнал; одиночный — только для топ-элиты с подтверждённым
  winrate по разрешённым сигналам.
- *Обоснование:* при медианном winrate китов 51% текущие 76% держатся на управлении
  выходом, а не на качестве входа. Чистые киты поднимут базовую долю правоты.

### P2 — выходы под высокий win-rate (↑ размер выигрышей)
- Симметрия риска: `stop_loss_delta −15c→−10c` (= TP) либо `take_profit_delta +12..15c`
  при SL −10c → R/R ≥ 1.0 (`src/config.py`).
- Флип: поднять `partial_take_delta +5c→+8c` или отключить (`partial_take_fraction 0`) —
  при 76% попаданий ранняя фиксация режет лучшие сделки (флип-зона avg +$1.44 vs TP +$3.70).
- Трейлинг-стоп вместо жёсткого TP: дать выигрышам ехать до разрешения (выход по 1.0),
  фиксируя откат.
- *Обоснование:* при PF 2.28 узкое место — величина, не частота.

### P3 — масштаб (после подтверждения edge)
- Поднять `position_max_pct 2%→3–4%` и/или банкролл только после ≥30 разрешённых сигналов,
  подтверждающих edge. Наращивать капитал на непроверенных китах преждевременно.

### P4 — покрытие разрешения спорт-рынков (опционально)
- 46/99 рынков не находятся в Gamma по `condition_ids`. Найти альтернативный лукап (CLOB
  `/markets/{cond}` или slug) или помечать такие сигналы closed по live-цене на момент
  `endDate`, чтобы петля их тоже учитывала.
